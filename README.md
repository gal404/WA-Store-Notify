# WA Store Notify — התראות וואטסאפ להזמנות WooCommerce

עדכוני וואטסאפ אוטומטיים ללקוחות על מצב ההזמנה (נקלטה / מוכנה לאיסוף / נשלחה עם מספר מעקב / פריט אזל או הוחלף), מועדון לקוחות ודיוור — עם הנדסת אנטי-חסימה מובנית.

## ארכיטקטורה — מודל משיכה (pull)

```
WooCommerce (hook) ──▶ תוסף WP ──▶ INSERT לתור (wsn_outbox, status=queued)
                                          │  REST wa-notify/v1 (HTTPS + מפתח API)
                                          ▼
                    הגשר (Node, על המחשב המקומי) ──claim──▶ שולח בקצב אנושי ──report──▶ עדכון סטטוס
                                          │
                    "הסר" נכנס בוואטסאפ ──optout──▶ הסרה מהמועדון + ביטול ממתינות
```

**למה משיכה:** אתר הוורדפרס עשוי לשבת באחסון מרוחק ולא יכול להגיע למחשב הביתי. הגשר יוזם את כל התקשורת — אין חיבור נכנס למחשב, אין ngrok. הוורדפרס אף פעם לא ממתין לוואטסאפ.

שני רכיבים:
| רכיב | טכנולוגיה | תפקיד |
|---|---|---|
| `plugin/` | תוסף WordPress (PHP, בלי framework) | hooks של WooCommerce, תור הודעות, מועדון, ממשק ניהול בעברית, REST API |
| `bridge/` | Node + whatsapp-web.js (Puppeteer) | מושך הודעות, שולח בקצב אנושי, מאזין ל"הסר" |

## התקנה

### 1. התוסף (WordPress)
העתק את `plugin/` אל `wp-content/plugins/wa-store-notify/` והפעל דרך מסך התוספים (דורש WooCommerce פעיל). ההפעלה יוצרת את הטבלאות ומוסיפה את היכולת `manage_wa_notify` למנהל ולמנהל חנות.

בתפריט **וואטסאפ לחנות ▸ הגדרות**: לחץ "צור מפתח" והעתק את המפתח (מוצג פעם אחת).

### 2. הגשר (המחשב המקומי)
```
cd bridge
copy .env.example .env      # ומלא WP_URL + API_KEY מהשלב הקודם
npm install                 # הורדה ראשונה מושכת Chromium (~150MB)
npm start                   # או כשירות רקע:
npx pm2 start ecosystem.config.js && npx pm2 save
```
פתח `http://127.0.0.1:3200` וסרוק QR (או השתמש בקוד צימוד) כדי לחבר את מספר החנות. הסטטוס יופיע גם ב-WP ▸ וואטסאפ לחנות ▸ סטטוס.

### 3. הגדרת התבניות
WP ▸ **תבניות** — הפעל תבנית לכל סטטוס הזמנה רלוונטי (כולל סטטוסים מותאמים), כתוב 2+ נוסחים לכל אחד (טקסטים זהים מעלים סיכון חסימה), ובדוק עם "שלח לי לבדיקה".

## פיתוח מקומי (XAMPP, http)
ה-REST דורש HTTPS בפרודקשן. לבדיקות על `http://localhost` בלבד, הוסף ל-`wp-config.php`:
```php
define('WSN_ALLOW_HTTP', true);
```
**להסיר בפרודקשן.**

## מניעת חסימה — מה מובנה

whatsapp-web.js אינו רשמי ויש סיכון חסימה שיורי. שכבות ההגנה (מוגדרות ב-WP ▸ הגדרות):
- **מרווח אקראי** בין הודעות (טרנזקציוני 30–90s, קמפיין 90–240s) + **שעות שקט** + **caps** לשעה/יום.
- **דימוי הקלדה** לפני כל שליחה, ו**אימות מספר** (לא שולחים למי שאינו בוואטסאפ).
- **וריאנטים** לכל תבנית — אין טקסטים זהים.
- **שגיאת כתיב מכוונת** אחת ל-X הודעות (שולח ומתקן תוך שניות עם `Message.edit`) — לעולם לא בתוך מספר מעקב/הזמנה/קישור.
- **מצב חימום** למספר טרי (10→25→50→100 ליום).
- **מפסק זרם**: 3 כשלונות רצופים → עצירה + התראה במייל וב-WP.
- **קמפיינים** רק ללקוחות עם הסכמת דיוור, בקצב איטי ובחלון צהריים בלבד.

> **המלצה:** מספר SIM ייעודי לחנות, ומצב חימום פעיל בשבוע הראשון. אל תריץ שני גשרים על אותו מספר.

## אבטחה
- מפתח API נשמר כ-hash בלבד (SHA-256), אימות ב-`hash_equals`, נעילת IP אחרי נסיונות כושלים, HTTPS חובה.
- כל `bridge/` חסום לגישת web (`.htaccess`) — `session/` היא קרדנציאל הוואטסאפ המלא. `session/`, `data/` ו-`.env` לא נכנסים לגיט.
- הודעות נכנסות מטופלות אך ורק כ-opt-out (התאמת מילה מדויקת), בלי הרצת פקודות. אין הורדת מדיה.

## מבנה קבצים
`plugin/includes/` — `class-wsn-outbox.php` (לב התור), `class-wsn-rest.php` (חוזה ה-API), `class-wsn-order-hooks.php` (hooks), `class-wsn-contacts.php` (מועדון), `class-wsn-campaigns.php`, ותיקיית `admin/` לממשק.
`bridge/src/` — `worker.js` (לולאת claim→send→report), `pacer.js` (קצב+caps), `typo.js`, `breaker.js`, `optout.js`, `senders/wwebjs.js` (מתאם השליחה, ניתן להחלפה ל-Green API/Cloud API).
